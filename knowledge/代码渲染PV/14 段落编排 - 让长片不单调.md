# 14 段落编排 - 让长片不单调

## 问题

一首歌 3~4 分钟。如果整片都是同一个镜头、同一个构图、同一个颜色，看到第 30 秒观众就走了。

**单镜头会单调，这是长片最大的风险，而且和"画面好不好看"无关。**

## 解法：把「画面随段落变化」做成数据

段落边界来自打点表的 `sections`，每个段落一套参数，放在 `input/staging.json`：

| 字段 | 作用 |
|---|---|
| `accent` | 主色（世界面板、高亮、气泡） |
| `worldScale` | 右侧世界面板的缩放（1 = 原始，>1 推近） |
| `gridDensity` | 格子的疏密 0~1 |
| `mandalaSpeed` | 中央字符云的演化速度倍率 |
| `camera` | `[段落开始, 段落结束]` 的全画面缩放 |
| `shake` | 随拍抖动的最大像素数 |

```json
"melody": {
  "accent": "#a371f7",
  "worldScale": 1.14,
  "gridDensity": 1.0,
  "mandalaSpeed": 2.0,
  "camera": [1.012, 1.016],
  "shake": 2
}
```

**改数值就能改画面，不用动代码。** 找不到的段落名自动回落到 `default`，所以换歌时可以先只改几个。

## ⚠️ 关键坑：全画面缩放会裁掉内容

> [!warning] 缩放不是"变大一点"，是**四周按比例裁切**
> `transform: scale(s)` 绕中心放大，每侧裁掉的宽度是 `W × (1 − 1/s) / 2`。
> scale = 1.05 时，1280 宽的画面上**每侧裁掉约 31 像素**。

我第一次把 `camera` 开到 1.26，结果：
- 左侧聊天面板的标题被切
- 底部状态栏整条被切掉一半
- 输入框只剩一条边

**而且这个问题在小尺寸预览里看不出来**——必须出静帧核对边缘。

### 安全区怎么算

```
每侧裁切像素 = W × (1 − 1/s) / 2
```

| scale | 1280 宽每侧裁掉 | 720 高每侧裁掉 |
|---|---|---|
| 1.02 | 12.5 px | 7.1 px |
| 1.03 | 18.6 px | 10.4 px |
| 1.05 | 30.5 px | 17.1 px |
| 1.10 | 58.2 px | 32.7 px |

**做法**：先定 `camera` 上限，再让界面所有文字元素距画面边缘 ≥ 那个值。
本项目的 `camera` 上限是 1.02，所以标题栏内边距取 22px、底部状态栏下边距取 20px。

## 正确的力度分配

> [!tip] 强变化放在抽象面板上，全画面只做小幅漂移
> - **全画面**：段落漂移最多 2%，再叠一个随拍呼吸 `flash × 0.006`。幅度小，但因为是**卡着拍**的，观感上是"画面在跟着音乐呼吸"，很有效。
> - **抽象面板**（没有可读文字的区域）：`worldScale` 可以在 0.9 ~ 1.24 之间大幅变化，裁掉边缘也无所谓。

这就是"哪里可以裁、哪里不能裁"的判断：**有文字的地方不能裁，抽象的地方随便裁。**

## 与「主次表」的关系

参考工程用两张表控制合成（见 [[04 图层与合成 - 替换素材不丢动效]]）：

- `COVER`：哪些时段由某个图层接管画面
- `LEAD`：这一刻谁是主角，另一边亮度降到 42%

本项目的 `staging.json` 是同一思路的简化版：**用数据描述"这一刻画面是什么状态"**，
而不是把状态写死在画面代码里。好处是调片时只改 JSON，不用碰代码，也不会引入 bug。
