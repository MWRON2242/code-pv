# 03 打点表 - 全片的地基

## 为什么它排第一

整支片子的**每一个画面切换、每一句字幕、每一次特效**都挂在时间点上。

- 素材可以后补
- 风格可以后改
- **时间点错了，全片重做**

所以顺序永远是：**先定歌 → 再做打点表 → 才谈画面**。

## 打点表长什么样

本质就是一张「时间 → 事件」的表：

```json
{
  "song": "test-track.wav",
  "duration": 25.5,
  "fps": 24,
  "markers": [
    { "i": 1, "t": 0.0,    "frame": 0,  "type": "cut",    "label": "开场" },
    { "i": 2, "t": 0.5,    "frame": 12, "type": "accent", "label": "" },
    { "i": 3, "t": 2.0,    "frame": 48, "type": "lyric",  "label": "第一句" }
  ]
}
```

**它是纯数据。** 跟用什么工具渲染无关，换工具也能用——这是它最大的价值。

## 四类点（本项目的约定）

| 类型 | 记什么 | 用途 |
|---|---|---|
| 切换 `cut` | 镜头切换 / 转场 | 决定画面什么时候换 |
| 重音 `accent` | 鼓点、音乐重音 | 决定什么跟着音乐抖 |
| 唱词 `lyric` | 唱词起音 | 决定字幕和呼应动作的落点 |
| 标记 `note` | 随手记 | 给自己看的提醒 |

> [!tip] 打点的时候只关心「听觉瞬间」，不要想画面
> 想着画面会犹豫，犹豫就打不准。先纯粹跟着音乐打，之后再分配画面。

## 精度要求

- 24 fps 时，一帧 = **41.7 毫秒**
- 偏离半帧（约 20ms）人耳/眼基本无感；偏离 2~3 帧就能看出来
- 所以打点要**吸附到帧**：`t = round(t × fps) / fps`

## 工具与流程

本项目的打点器：`code-pv/tools/tapper/index.html`（双击打开，零安装，音频不上传）

1. 拖入音频
2. 空格播放，按 `1/2/3/4` 落点
3. `←/→` 微调 1 帧，`Shift+←→` 跳 1 秒，`退格` 删除，`Ctrl+Z` 撤销
4. 放大到 40 倍可以逐帧对
5. 导出 `markers.json`

## 验证方法

无版权测试音轨自带**标准答案**（`input/test-track.beats.json`）：

- 120 BPM → 每拍正好 **0.500 秒**
- 拿你打的点跟标准答案比，偏差超过 ±0.03 秒就要检查

## 纯器乐的特殊情况

没有歌词就**不需要逐词对齐**，只做鼓点/重音打点即可，难度低很多。

有歌词时，逐词对齐是最麻烦的一步——可以先用 LRC 的行级时间凑合，把样片跑通，之后再升级到逐词。
