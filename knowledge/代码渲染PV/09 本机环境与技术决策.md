# 09 本机环境与技术决策

## 环境探测结果

| 组件 | 状态 | 说明 |
|---|---|---|
| Node.js | ✅ v24.21.0 | 主力运行时 |
| npm | ✅ 11.19.0 | |
| git | ✅ 2.55.0 | |
| **Python** | ❌ 未安装 | 只有微软商店的占位快捷方式（那种"假 python"，双击会跳商店） |
| **ffmpeg** | ❌ 未安装 | Remotion 自带，所以选了它就不用装 |
| NVIDIA GPU | ❌ 无 | 渲染走 CPU，时间按分钟计 |
| winget | ✅ 可用 | 以后要装东西可以用它 |

## 技术决策：为什么选 Remotion

| 候选 | 判断 |
|---|---|
| **Remotion** ✅ | Node 已就绪，**零额外安装**；自带 ffmpeg 和 Chromium；有浏览器实时预览（能像剪辑软件一样拖时间轴）；文档示例最多。许可：个人及 ≤3 人公司免费 |
| Motion Canvas | MIT 许可更宽松，但导出需要系统里有 ffmpeg（本机没有），生态也少 |
| Python 自建引擎 | 需要先装 Python + ffmpeg；每次渲染完才知道效果；无 GPU 很慢 |

**决定性因素**：Remotion 把 ffmpeg 和 Chromium 都打包好了，所以在这台「有 Node、没有别的」的机器上可以**零安装立刻开工**。

## 工程结构

```
code-pv/
├─ PLAN.md                全流程路线图
├─ ASSETS.md              素材授权登记表
├─ package.json           Remotion 工程
├─ remotion.config.ts     渲染配置
├─ src/
│  ├─ index.ts            入口（登记根组件）
│  ├─ Root.tsx            「影片登记处」：每个 Composition = 一条可渲染的成片
│  └─ BeatTest.tsx        里程碑 1：把打点表画出来
├─ input/                 打点表、标准答案
├─ public/audio/          Remotion 能读取的音频（staticFile 从这里找）
├─ knowledge/             本笔记库
├─ tools/
│  ├─ tapper/             打点器（浏览器打开就用）
│  └─ make-test-track.mjs 生成无版权测试音轨
└─ out/                   成片与母版
```

**为什么音频要放在 `public/`**：Remotion 的 `staticFile()` 只从 `public/` 里找静态资源。`input/` 是「源数据」，`public/` 是「渲染时能读到的资源」。

## 踩过的坑

### 坑 1：npm install 报 EPERM（路径类）

**现象**：`npm error code EPERM ... path C:\Users\jeffx\AppData\Local\npm-cache\_cacache\tmp\...`

**原因**：npm 默认把缓存放在用户目录，而工作区沙箱只允许写工作区内部。

**解法**：把缓存重定向进工作区，**不申请更高权限**：

```powershell
$env:npm_config_cache = 'D:\deepseek工作区\.npm-cache'
npm install ...
```

### 坑 2：spawn EPERM（管道类，绕不过）

**现象**：`npm error code EPERM, syscall: spawn` 或渲染时直接 `spawn EPERM`

**原因**：受限沙箱禁止**命名管道**。任何用管道捕获子进程输出的操作都会失败——
npm 要运行依赖包的安装脚本、Remotion 要启动打包进程和无头浏览器，全都中招。

**这类错误和路径无关，重定向没用。** 只有两条路：

1. 让沙箱处于不受限模式（本项目采取的方案）
2. 在 DSH 之外的普通终端里手动跑命令

### 坑 3：ffmpeg 写系统临时目录被拒

**现象**：`Error opening output C:\Users\jeffx\AppData\Local\Temp\react-motion-renderXXXX\pre-encode.mp4: Permission denied`

**原因**：Remotion 用系统临时目录存放编码中间文件，该目录在沙箱外。

**解法**：同样重定向进工作区：

```powershell
$env:TEMP = 'D:\deepseek工作区\.tmp-render'
$env:TMP  = 'D:\deepseek工作区\.tmp-render'
```

### 坑 4：React 版本冲突（ERESOLVE）

**现象**：`ERESOLVE could not resolve` / `Found: @remotion/cli@undefined`

**原因**：npm 默认装了 React 19，与 Remotion 的依赖树冲突；且第一次安装失败留下的
残缺 node_modules 会污染第二次安装。

**解法**：清干净 + **版本锁死**：

```powershell
Remove-Item -Recurse -Force node_modules, package-lock.json
node $npmCli install --save-exact remotion@4.0.532 @remotion/cli@4.0.532 react@18.3.1 react-dom@18.3.1
```

### 通用规律

> [!important] 遇到 EPERM / Permission denied，先问两个问题
> 1. **这个路径在工作区里吗？** 不在 → 重定向进去（缓存、临时目录都能改）
> 2. **是在启动子进程吗？** 是 → 管道限制，重定向无效，只能放宽沙箱

## 实测效果（里程碑 1）

612 帧 / 1280×720 / 含 aac 音轨，**渲染耗时 31.6 秒**。CPU 渲染完全够用，
不必因为没 GPU 而担心——真正的瓶颈是设计和调试，不是渲染速度。
