# 11 分镜与转场 - 把镜头排成片

单个镜头会做了（[[10 从打点表到画面 - f(t) 怎么写]]），接下来是把镜头排成一支片。这一步比想象中简单，但有三个坑。

## 核心：所有镜头共享同一个全局 `t`

因为是 `f(t)`，切换镜头**不需要任何偏移量**。分镜表就是一个数组：

```json
{
  "scenes": [
    { "id": "intro", "scene": "player", "from": 0.0, "to": 8.0, "fadeIn": 0.6, "fadeOut": 0.5 },
    { "id": "main",  "scene": "chat",   "from": 8.0, "to": 25.5, "fadeIn": 0.5, "fadeOut": 0.8 }
  ]
}
```

渲染时逐个算透明度，大于 0 才挂载：

```ts
const inPart  = fadeIn  > 0 ? clamp01((t - from) / fadeIn)  : (t >= from ? 1 : 0);
const outPart = fadeOut > 0 ? clamp01((to - t) / fadeOut)   : (t <= to   ? 1 : 0);
const opacity = inPart * outPart;
```

**好处**：加镜头、改时长、调顺序，全都只改 JSON。代码一行不动。

## 转场怎么选（本片踩过坑）

| 方式 | 怎么做 | 什么时候用 |
|---|---|---|
| 硬切 | 两段首尾相接，不带 fade | 节奏点；版式相同的镜头之间 |
| 交叉溶解 | 两段重叠，两边都有 fade | **只有版式相近时才用** |
| **黑场过渡** | `to` 等于下段的 `from`，各自 fade | **版式差异大时用**（本片的选择） |
| 闪白 | 同上但过白 | 强冲击、段落大转折 |

> [!warning] 踩过的坑：交叉溶解变成重影
> 本片开头是「播放器歌词页」（左右两栏），主体是「聊天窗口」（46/54 分栏）。
> 一开始用了 1.2 秒交叉溶解 → 两套版式叠在一起，**文字压文字，完全读不出来**。
> 改成黑场过渡（淡出到黑 0.5 秒 → 黑淡入 0.5 秒）后立刻干净了。

**判断法则**：两个镜头的**构图骨架**不同 → 走黑场；相同或相近 → 才可以溶解。

## 第二个坑：音频播了两遍

场景组件里通常各自带一个 `<Audio>`。转场时两个组件同时挂载 →
**同一段音频被叠成两轨，音量翻倍、还有相位抵消**。

> [!important] 音频只在顶层放一次
> 把 `<Audio>` 提到组装组件（`MainFilm`）里，场景组件通过 prop 关掉自己的那份：
> ```tsx
> <Comp audio={false} />
> ```
> 单独预览某个镜头时仍然可以 `audio` 默认为 `true`，两不耽误。

## 第三个坑：透明度为 0 的组件还在渲染

如果只把 `opacity` 设成 0 而不卸载，Remotion 仍会渲染它 —— 白白浪费时间。
要在 `opacity <= 0.002` 时直接 `return null`。

## 数据入口只有一个

把所有会随歌改变的东西集中到一个模块（本项目的 `src/lib/song.ts`）：

```
歌曲时长 / 拍点 / 段落   ←  input/*.beats.json
聊天台词                ←  input/script.json
歌词                    ←  input/lyrics.json
分镜表                  ←  input/timeline.json
音频                    ←  public/audio/*
```

**换歌 = 换这 5 样东西，代码零改动。** 这是整个架构最重要的一条纪律。
