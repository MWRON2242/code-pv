# 15 让单镜头扛住 3~4 分钟

用户拍板：**只用两个镜头**（D 播放器页做引入 → A 聊天窗口扛主体）。

那么 A 要独自撑住 3~4 分钟。这不是审美问题，是**注意力**问题。
核心目标一句话：

> **一直在动，但不烦人。**

"动"负责让画面活着，"不烦人"负责让观众不被干扰。两者要分开实现：

| 层次 | 负责什么 | 变化尺度 | 频率 |
|---|---|---|---|
| 微运动 | 画面"活着" | 几个像素 | 每秒都在变 |
| 卡点 | 画面"合拍" | 局部亮度/位置 | 每拍一次 |
| 段落编排 | 画面"有变化" | 构图与配色 | 每段一次（十几秒到一分钟） |

**如果只有卡点，会显得机械；只有段落编排，中间会空；只有微运动，会显得没精神。**
三者叠加才是"一直在动但不烦人"。

## 六种持续供氧的手法（本项目实际用的）

### 1. 消息要有退场动画（最容易漏的一条）

聊天窗口只显示最近 N 条。**第 N+1 条出现时，最旧那条如果直接消失，会非常刺眼**——
而且在长片里每十几秒就刺一次。

实现要点：列表**多取一条**，让"正要被挤出去"的那条有机会播完退场。

```tsx
const shown = all.slice(-(SHOW + 1));      // 多取一条，留给退场

shown.map((m, i) => {
  const newer = shown.length - 1 - i;      // 比它更新的有几条
  const exiting = newer >= SHOW && all.length > SHOW;
  // 退场从「第 SHOW 条更新的消息」到达时开始 —— 也就是它被挤出窗口的那一刻
  const exitStart = shown[i + SHOW] ? shown[i + SHOW].t : Infinity;
  const outP = exiting ? Math.min(1, (t - exitStart) / 0.3) : 0;
  const op = appear * (1 - outP);
  // 位移：进场从下往上，退场继续往上飘
  transform: `translateY(${(1 - appear) * 14 - outP * 10}px)`
})
```

**关键是 `exitStart` 取的是「第 SHOW 条更新消息」的时间**，而不是"当前时间"——
否则所有旧消息会一起淡出。

### 2. 每条消息带时间码

一行小小的 `00:12.12`。看起来是装饰，实际在做两件事：
- 强化"时间在走"，让静止画面有进度感
- 和时间轴上的音乐对应，观众潜意识里会把画面和歌绑起来

### 3. 顶栏换成随拍跳动的迷你波形

参考工程也做了这件事（把顶栏换成歌曲的实时波形）。
**把界面装饰和音乐绑起来，是性价比最高的一招**——它让"UI 画面"不再和音乐脱节。

实现就是几十根小柱子，高度 = `伪随机 × exp(−距上一拍的时间 × 3.4)`。

### 4. 数据流：持续的微运动

右侧世界面板加一列滚动的十六进制数字。它是"背景噪音"级别的存在，
但**只要它在动，画面就不是死的**。

要点：
- 用**确定性伪随机**（见 [[10 从打点表到画面 - f(t) 怎么写]]），同一帧永远同一串
- 用 CSS `mask-image` 让上下两端渐隐，避免硬边缘
- 透明度压低（本项目 0.5），它不该抢注意力

### 5. 每拍一道扫描线

每拍有一道横向亮线扫过世界面板，0.5 秒走完，同时淡出。
**它是最便宜的"标点符号"**——让观众感知到拍子，但不占据画面。

### 6. 段落编排负责大尺度变化

见 [[14 段落编排 - 让长片不单调]]。主色、构图、推近程度每段一变。

## 一条通用判断

> [!tip] 长片里，任何"突然出现/突然消失"的元素都是敌人
> 元素出现要有进场，消失要有退场。静止的背景要有微运动。
> 观众说不清哪里不对，但会觉得"闷"或者"跳"。
