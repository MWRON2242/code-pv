# 16 一个会挂死的 bug - 数值异常绝不该变成死循环

这个 bug 在 25 秒的测试音轨上一切正常，换成 3 分 30 秒的彩排音轨后**直接卡死**。
值得单独记下来，因为它同时暴露了三个工程习惯问题。

## 现象

`tools/auto-beats.mjs` 跑彩排音轨时没有任何输出，也不报错。看进程才发现：

```
PID 35812   CPU 1165 秒   启动于 20 分钟前
```

**一个核心被占满 20 分钟，而且什么都没打印。**

## 根因

节拍检测里有一段「八度修正」——自相关经常把周期识别成 2 倍或 1/2 倍，
所以要把它锁回人耳习惯的 80~160 BPM：

```js
// ❌ 错误
while (bpm < 80) {
  period *= 2;
  bpm = (60 * ENV_RATE) / period;
}
```

`bpm = 60 × 采样率 / period`。**周期加倍 → BPM 减半。**
所以 BPM 越小、循环越继续，永远出不来。

正确方向是**周期减半才能让 BPM 加倍**：

```js
// ✅ 正确
while (bpm < 80) period /= 2;
while (bpm > 160) period *= 2;
```

## 为什么藏了这么久

之前那条测试音轨是 **120 BPM**，正好落在 80~160 区间内 ——
**两个 while 分支都不执行**，所以这个错误从来没被触发过。

彩排音轨是 128 BPM。一旦自相关把周期识别成 80.8 帧（半速，即 64 BPM），
`bpm = 64 < 80` 成立，立刻进入死循环。

> [!warning] 教训：只在一种输入上验证过的代码，等于没验证
> 120 BPM 是一个「恰好绕开所有边界」的输入。**边界值必须专门测。**

## 同一处的另外两个隐患

排查时发现同一个文件里还有两个会跟着一起爆的地方：

1. **抛物线插值会发散。**
   自相关曲线平坦时 `denom = y0 − 2y1 + y2` 趋近 0，而修正量是 `0.5(y0−y2)/denom`，
   可能算出几十万帧的周期。

   ```js
   // 相对阈值 + 区间检查，两道都要有
   const scale = Math.max(Math.abs(y0), Math.abs(y1), Math.abs(y2), 1e-9);
   if (Math.abs(denom) > scale * 1e-2) {
     const refined = best.lag + (0.5 * (y0 - y2)) / denom;
     if (isFinite(refined) && refined >= minLag - 1 && refined <= maxLag + 1) lag = refined;
   }
   ```

2. **相位穷举的步数跟着周期走。**
   `const steps = Math.round(period * 8)` —— 周期一旦变成 10 万，这个循环就是 80 万次
   外层迭代，每次内层还要扫全曲。

   ```js
   const steps = Math.min(2000, Math.max(40, Math.round(period * 8)));  // 加个上限
   ```

## 三条防御原则

1. **数值修正必须夹范围**：既要用相对阈值判断「这个修正可信吗」，也要用区间检查兜底。
2. **所有循环都要有上限**：`while (条件)` 里只要条件依赖浮点计算结果，就加一个 `guard++`。
3. **边界值要专门测**：把参数推到区间外（这里是 BPM < 80 和 BPM > 160），看会发生什么。

> [!important] 死循环是最糟的失败方式
> 报错会告诉你哪里错了；**死循环什么都不说，只是耗掉你的时间和电。**
> 所以「加循环上限」这件事的性价比极高——它把最难诊断的故障，变成一条日志。

## 顺带验证到的好消息

修完之后，彩排音轨（211 秒）的检测**只用了 1 秒**，而且：

| 检查 | 结果 |
|---|---|
| BPM | 127.97（真值 128，误差 0.02%） |
| MP3 vs WAV | 相差 2 毫秒 —— **MP3 编码延迟不构成问题** |
| 小音轨回归 | 仍然 48/48 落在 10 毫秒内 |
| 密集混音精度 | 中位 10.7~12.6 毫秒，100% 落在 50 毫秒内 |

密集混音精度比小音轨差一些（2.2ms → 12.6ms），原因是 16 分音符踩镲让起音峰变密，
吸附时容易落到相邻峰上。**仍在四分之一帧以内**，可用；想更准就用打点器人工核对。
