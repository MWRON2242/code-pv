# 01 核心概念 - 时间是一等公民

## 传统剪辑 vs 代码渲染

| | 传统剪辑 | 代码渲染 |
|---|---|---|
| 素材 | 先拍好，再摆到轨道上 | 不存在，每一帧现算 |
| 时间轴 | 软件的界面（工程文件里） | 代码里的一个变量 `t` |
| 调整 | 拖一下，立刻看到 | 改参数，重新渲染 |
| 产物 | 工程文件 + 成片 | 只有代码；成片是代码的输出 |
| 可复现 | 依赖软件版本、插件、手速 | 同一份代码 → 同一帧，永远 |

## `f(t)` 到底是什么意思

```
第 t 秒的画面  =  f(t)
```

`f` 是一段代码。给它一个时间点，它算出那一刻画面上有什么、在哪里、什么颜色。

关键性质：**没有「上一步」的概念。** 第 100 帧不需要知道第 99 帧长什么样，它自己就能算出来。

这和手绘动画的区别：手绘动画每一帧都要人画；代码渲染是写一个**函数**，覆盖全部帧。

## 这么做换来什么

1. **确定性**：同一份代码永远出同一帧。所以能改分辨率重出、能只重渲染某一段
2. **可数值比对**：两个版本可以逐像素算差值，找出哪一帧变了（参考工程就是这么验收的：几千张截图 + 母版差异筛选）
3. **参数化**：改一个数字，全片 96 个镜头一起变
4. **能并行**：帧之间互不依赖，可以多核同时算

## 代价

1. **看不到即时反馈**：除非工具带实时预览（[[08 工具谱系]] 里的现代框架都带）
2. **渲染慢**：CPU 渲染一支 3~4 分钟的片子，几十分钟很正常；没有 GPU 更慢
3. **有机细节难做**：手绘的笔触、真实的质感，代码算出来容易「太干净」
4. **调试靠数字**：画面不对时，你面对的是报错和坐标，不是可视化的界面

> [!warning] 最容易低估的一点
> 代码渲染**不等于**省事。它把「剪辑的时间」换成了「写代码和调试的时间」。
> 好处是这份时间**可以复用**：改一次规则，全片重出。

## 和剪辑对得上的地方

- `t` ↔ 时间轴上的时间码
- `f(t)` ↔ 你在某一帧做的所有调整的总和
- 帧率（24/25/30）↔ 完全一样，只是代码里要显式写出来
- `t` 必须**卡在帧上**：24fps 时最小单位是 1/24 秒 ≈ 41.7 毫秒
