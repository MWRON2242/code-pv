# 05 四个层级 - 代码覆盖到哪一层

「代码出片」不是一件事，是一个谱系。区分标准只有一个：**代码负责到哪一层。**

| 层级 | 代码负责什么 | 典型做法 | 是「一个完整程序」吗 |
|---|---|---|---|
| **0** | 不参与画面 | 剪辑软件手工做、AE 模板 | 否 |
| **1** | 只生成素材 / 预演 | 脚本批量导素材、Blender 脚本、Houdini VEX，再手工剪 | 否，是片段工具 |
| **2** | 全部画面，但时间线是**声明式场景描述** | Remotion、Motion Canvas、Manim | 是一个项目，但不是自建引擎 |
| **3** | 全部画面 + **自建渲染引擎** | 参考工程、手写绘图库、p5.js/Three.js | 是，最接近「完整程序」 |
| **4** | 实时、不可精确复现 | TouchDesigner 节点、VJ 软件、Live Coding | 是程序，但输出不确定 |

## 怎么理解这几个层级

**层级 1**：等于「用脚本批量导素材，然后手工剪」。最省事，但每次改都要重剪。

**层级 2**：等于「剪映模板那类自动化工具」——你填内容，它排版。**绝大多数人应该从这里开始。**

**层级 3**：等于「自己造了一个 AE」。参考工程就在这里。好处是质感完全可控，代价是工作量巨大。

**层级 4**：等于 VJ 现场，好看但同一秒不会出现第二次。**不适合做要发布的成片。**

## 关键结论

> [!important] 语言不是门槛
> 「代码出片」不等于「一个完整的 Python 程序」。
> 同样走层级 3，可以用 Python、TypeScript、GLSL、C++、Rust 或任何语言。
> 真正的门槛是**把时间轴写进代码**（见 [[01 核心概念 - 时间是一等公民]]）。

## 同一个 MV，不同层级的工程量

| 层级 | 大概规模 |
|---|---|
| 2 | 几百行，几天 |
| 3 | 几千行，几周到几个月 |

参考工程属于层级 3，还额外带了逐帧截图、补丁链、数值验收——所以它的复杂度远高于同题材的层级 2 作品。

## 选层级的建议

1. 先问：**我需不需要那种完全自定义的质感？**
2. 如果不需要 → 层级 2，用现成框架，把精力花在内容和分镜上
3. 如果需要 → 先用层级 2 把片子的**结构和节奏**验证出来，再考虑是否下沉到层级 3
4. **永远不要一上来就写引擎**
